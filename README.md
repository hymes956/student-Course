# 大学生选课系统 · 前端演示

一个**零依赖、零构建、不联网**的选课系统演示工程。双击 `demo/index.html` 就能跑，
不需要装 Node、不需要起服务、不需要后端。

课程方向：数字建筑 / 建筑设计 / 智能建造 / 空间计算与图形学。

---

## 快速开始

把仓库拿到本地（`git clone`，或页面右上角 **Code → Download ZIP**），然后：

```bash
cd <仓库目录>/demo
open index.html          # macOS
# Windows 直接双击 index.html；Linux 用 xdg-open index.html
```

（`2023002` ~ `2023006` 也能登录，各自的选课情况不同）

```bash

# 浏览器打开 http://127.0.0.1:8899

## 这个演示在讲什么

不是"点着玩的假页面"——页面上能点的东西背后都是真跑的业务逻辑：

| 能力 | 说明 |
|---|---|
| **选课并发控制** | 三种实现（朴素 / 唯一索引 / 条件扣减）并排跑，真的会超卖 |
| **候补队列 + 自动递补** | 满员可排队，退课按顺序自动补位并推消息 |
| **时间冲突检测** | 星期 + 节次区间 + 周次区间 + 单双周，四重判定 |
| **签到码时效** | 6 位码 60 秒自动刷新，过期即失效；前 5 分钟算准时，之后算迟到 |
| **作业提交与批改** | 截止判定、迟交标记、分数段统计、CSV 成绩单导出 |
| **教务统计看板** | 容量利用率、出勤率、作业提交率，全部实时算出来 |
| **AI 选课推荐** | 5 个维度加权打分，每条建议都能追溯到具体数据；选完立刻重算 |
| **学业预警** | 6 条规则分三档，每条预警能展开到具体作业 / 签到；解除靠重算不靠点掉 |
| **消息联动** | 选课 / 递补 / 签到 / 交作业 / 批改 / 催交 都会推消息 |

### 最值得看的一页：并发实验室

同一个业务函数写三种实现，在真实浏览器里跑真实的竞态。100 个并发请求抢 10 个名额：

| 实现 | 实际落库 | 超卖 |
|---|---|---|
| 朴素实现（先查后写） | **100 人** | **超卖 90** |
| 朴素 + 唯一索引 | **100 人** | **超卖 90** |
| 条件扣减（原子） | **10 人** | **0** |

结论：**两道防线缺一不可**——唯一索引防重复选，条件更新防超卖。

浏览器是单线程的，但 `await` 会让出事件循环，**这就是真实竞态**（真实系统里对应网络往返 +
线程调度），只是被放大了。

### AI 选课推荐：能解释的分数

`demo/assets/ai.js` 是个**规则引擎，不是大模型**。先按硬约束把选不了的剔掉（已选 / 同课不同班 /
时间冲突 / 超学分上限），剩下的才进打分：

| 维度 | 权重 | 看什么 |
|---|---|---|
| 方向匹配 | 30 | 与主修方向是否一致、已修同方向课程数 |
| 课程衔接 | 25 | 先修课是否修过、课程层级是否正好衔接 |
| 课表负担 | 20 | 与现有课表的间隔、当天已有门数 |
| 名额情况 | 15 | 剩余名额；满员则给出候补排位 |
| 教师熟悉度 | 10 | 这位老师带过的课你的平均分 |

每张推荐卡都能展开「评分明细」，逐项列出得分和依据 —— 所以任何一条建议都能被追问，
而不是"AI 说的"。选完一门课，列表、学分、筛选计数立刻重算，不是写死的静态页。

接真模型只需要换 `AI.provider`，页面和调用方都不用动。

### 学业预警：让"该管谁"这件事可核对

`demo/assets/warning.js` 同样是规则引擎。它不引入任何新数据源 —— 签到、作业逾期、
已修学分本来就在库里，只是**没有人把它们串起来看某个学生是不是已经掉队了**。

6 条规则分三档，每档的界线是"有没有真的造成损失"，不是分数高低：

| 档位 | 含义 | 典型触发 |
|---|---|---|
| 关注 | 有苗头，还没损失 | 逾期 2 份、单次作业不及格、学分慢于同年级 |
| 预警 | 已经影响成绩 | 逾期 ≥ 4 份、出勤率 < 80%、课程均分 < 70 |
| 严重 | 已危及学分 | 缺勤 ≥ 4 次、均分 < 60、多维度叠加 |

两个刻意的设计：

**阈值用「相对位置 + 绝对下限」双条件。** 这套种子数据的学分是按档生成的
（20/26/32/38/44），任何单一绝对阈值都会把整档学生一次性标红。实测：
学分规则命中 18/90 = 20%，而全校总预警率 38.9%、正式预警率 21.1% —— 分布是有区分度的，
不是"人人有份"。

**解除靠重算，不靠人工点掉。** 干预（提醒 / 约谈 / 联系家长）只写记录、把状态推进到
`intervening`，**不会**消掉预警。只有补齐作业后重算，规则不再命中，才会自动转
`resolved` 并写明原因。这是整个功能里最容易被做成"点一下没了"的地方。

林晓阳（`2023001`）是最适合演示的样本：**出勤 3/3 全勤，但 5 份作业逾期** ——
只看出勤他会漏掉，只看作业又解释不了他为什么还有 42 学分。多维度才看得出问题。

```

## 技术选择说明

**为什么不用框架、不用 ES module？**

这是整个工程最关键的约束：ES module 在 `file://` 协议下会被 CORS 拦死，
双击 `index.html` 直接白屏。所以四个文件全部用 `<script src>` 顺序加载 + IIFE 挂全局，
**主动放弃了模块化**——换来"拿到就能打开"。

这条路径已实测（Chromium，`file://`）：脚本加载、CSS、localStorage、
11 个路由渲染、并发实验、刷新保持登录态、重置数据，全部通过。

> Safari 对 `file://` 更严格，CSV 导出可能被拦。要在 Safari 演示导出功能，请用本地服务器方式。

## 已知边界

- **不是真并发**。用 `await` 让出事件循环来复现竞态窗口，竞态是真的，只是被放大了。
- **文件上传是假的**。只记录文件名和大小，不做真实上传。
- **没有权限校验**。前端能改任意数据；真实系统必须服务端校验 + 越权检查。
- **签到没有防代签**。真实系统还需要定位围栏 / 设备指纹 / 二维码签名。
- **统计都是实时全量计算**。数据量大了要预聚合，不能每次扫全表。

更详细的边界说明见 `demo/README.md`。
