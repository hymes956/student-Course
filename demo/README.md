# 大学生选课系统 · 前端演示

纯前端演示工程。**零依赖、零构建、不联网**，双击 `index.html` 就能跑。

课程方向：数字建筑 / 建筑设计 / 智能建造 / 空间计算与图形学

## 怎么打开

**方式一（推荐，双击即可）**
直接双击 `index.html`。

**方式二（本地服务器，Safari 下更稳）**
```bash
cd demo
python3 -m http.server 8899
# 浏览器打开 http://127.0.0.1:8899
```

演示账号：学号 `2023001`，密码 `123456`（`2023002` ~ `2023006` 也能登录，选课情况各不相同）

> 数据保存在浏览器 localStorage。想恢复初始状态：左侧栏底部「重置演示数据」，或到「个人中心」重置。

### 为什么必须用 classic `<script>`（这是本工程最关键的约束）

ES module 在 `file://` 协议下会被 CORS 拦死，双击 `index.html` 直接白屏。
所以五个文件全部用 `<script src>` 顺序加载 + IIFE 挂全局，**放弃了模块化**。

这条路径**实测过**，不是"应该可以"。验证方法（顺便证明浏览器没开宽松参数）：

```js
// 在 file:// 页面里执行。被拦 = 浏览器没开 --allow-file-access-from-files，
// 也就是和用户真实双击的环境一致
fetch('assets/data.js').then(r => 'fetch 成功 → 环境不真实').catch(e => '被拦 → 验证有效');
```

`file://` 下逐项确认过：脚本加载、CSS 加载、localStorage 可读写、
12 个路由渲染、并发实验（结果与 http 下完全一致）、刷新保持登录态、重置演示数据。

> ⚠️ **唯一没验证的是 Safari**。Chromium 下 CSV 导出的 blob URL 是 `blob:null/...`
> （`file://` 的 origin 是 null），能正常下载；Safari 对 `file://` 更严格，可能拦掉。
> **要在 Safari 里演示导出功能，请用方式二起本地服务器。**

## 这不是"点着玩"的假页面

页面上能点的东西，背后都是**真跑的业务逻辑**，不是写死的文案：

| 能力 | 实现位置 | 说明 |
|---|---|---|
| 选课并发控制 | `store.js` `enroll()` | 三种实现（朴素 / 唯一索引 / 原子扣减），真的会超卖 |
| 候补队列 + 自动递补 | `store.js` `joinWaitlist()` / `promoteFromWaitlist()` | 满员可排队；有人退课按顺序自动补位，**递补本身也是并发敏感点** |
| 时间冲突检测 | `store.js` `findConflict()` | 星期 + 节次区间 + 周次区间 + 单双周，四重判定 |
| 学分上限校验 | `store.js` `selectCourse()` | 超限直接拒绝 |
| 签到码时效 | `store.js` `checkIn()` | 6 位码 60 秒自动刷新，过期即失效 |
| 出勤状态判定 | `store.js` `checkIn()` | 开始 5 分钟内算准时，之后算迟到，窗口关闭算缺勤 |
| 作业截止判定 | `store.js` `submitHomework()` | 过期 + 不允许迟交 = 拒绝提交；允许迟交则打标记 |
| 批改统计 | `store.js` `gradingStats()` | 已交 / 已批改 / 未提交 / 平均分 / 分数段分布，全部实时算 |
| 名单与成绩单导出 | `store.js` `rosterCsv()` / `gradeCsv()` | 生成真 CSV（带 BOM，Excel 不乱码） |
| 教务统计 | `store.js` `statsOverview()` / `statsByCategory()` / `statsOfferings()` | 容量利用率、出勤率、作业提交率 |
| 消息联动 | `store.js` `pushMessage()` | 选课 / 递补 / 签到 / 交作业 / 批改 / 催交 都会推消息 |
| 数据持久化 | `store.js` `save()` | localStorage；`file://` 下被禁用时自动降级为内存态 |

`data.js`、`store.js`、`ai.js`、`grading.js`、`warning.js` **都不依赖 DOM**，
可以用 node 直接跑测试（125 条断言）：

```bash
cd demo
node selftest.js        # 输出全部 PASS 后打印「全部通过 ✅」
```

## 演示脚本（照着走一遍，约 8 分钟）

### 1. 选课闭环
1. 登录 `2023001 / 123456`
2. 左侧「课程广场」→ 点方向标签筛选（数字建筑 / 建筑设计 / 智能建造 / 空间计算与图形学）
3. 找 **《居住建筑设计》** → 点「选课」→ 成功，余量从 12 变 11
4. 找 **《三维空间建模与重建》** → 点「选课」→ **被拒绝：与《BIM 建模与协同》时间冲突**（周二 3-4 节）
5. 找 **《数字建造工作营》** → 已满，按钮置灰
6. 左侧「我的课表」→ 周视图，8 个时段

### 2. 签到闭环（重点）
1. 左侧「教师端」→ 选《BIM 建模与协同》→ 点「**发起签到**」
2. 屏幕出现 6 位签到码，下面有个进度条在跑 —— **每 60 秒自动换码**
3. 观察右侧「签到看板」：31 个学生全部显示缺勤
4. 左侧「课程签到」→ 点「一键填入」（演示助手，真实系统不会显示）→ 「提交签到」
5. 回「教师端」→ 看板上该学生变成「**出勤**」
6. 演示要点：签到码存 Redis 且有 TTL，所以能防拍照外传；超过 5 分钟才签算迟到

### 3. 作业闭环
1. 左侧「我的作业」→ 6 项，其中《光栅化渲染管线实现》已截止
2. 顶部筛选分四档：**全部 6 / 待提交 4 / 已完成 1 / 已截止 1**（四档加起来正好等于全部）
3. 点《光栅化渲染管线实现》→ **提交入口已关闭**（截止 9-20，且该作业不允许迟交）
4. 点《居住单元空间分析》→ 填写内容 + 选个文件 → 提交 → 状态变「已提交」
5. 回「教师端」→ 底部「作业批改」→ 打分写评语 → 保存
6. 回「我的作业」→ 状态变「已批改」，显示分数

### 4. 候补递补闭环（**并发敏感点，容易被忽略**）
1. 「课程广场」→ 找已满的 **《数字建造工作营》** → 按钮是黄色的「候补（N 人排队）」
2. 换一个没选过这门课的学生登录（比如 `2023002 / 123456`）→ 点「加入候补队列」→
   提示「候补第 N 位」，课程详情页能看到整条候补队列
3. 左侧「教务看板」→ 拉到底部「候补队列」→ 点「**模拟一名学生退课**」
4. 观察结果：`已选/容量` 仍是 20/20（**没有超卖**），候补人数 8 → 7，队首前移一位
5. 被递补的那个学生「消息通知」里收到一条《候补成功：…已自动选上》

**要讲的结论**：退课时先减名额、再取队首补位，这两步之间同样不能有间隙，
否则一次退课可能补进两个人。实现见 `store.js · promoteFromWaitlist()`，
用 `while (selectedCount < capacity)` 兜住。

### 5. 教务统计看板
1. 左侧「教务看板」→ 四个 KPI：开课班数 / 已选人次 / 平均出勤率 / 作业提交率
   （**这些数字都是实时算出来的**，改选课或签到数据会跟着变）
2. 「各课程方向选课分布」→ 4 个方向的容量利用率横向条
3. 「容量利用率排行」→ 按利用率排序，每行有「名单」按钮 → 导出该班选课名单 CSV
4. 「候补队列」→ 见上一节的递补演示

### 6. 教师端批改统计（答辩加分项）
1. 「教师端」→ 底部「作业批改」→ 顶部四个指标：提交情况 / 已批改 / 平均分 / 未提交
2. 下方「分数段分布」柱状图，打分后实时变化
3. 筛选器：`全部提交 / 待批改 / 已批改 / 未提交` 四档切换
4. 点「**催交（N 人）**」→ 弹出提示；若当前登录学生在未提交名单里，他会收到一条催交消息
5. 点「**导出成绩单**」→ 下载 CSV，含已交明细 + 未提交名单两段

> CSV 都带 UTF-8 BOM，Excel 直接打开中文不乱码。

### 7. 并发实验室（**最能拿分的一页**）
1. 左侧「并发实验室」
2. 参数保持默认：**100 个并发请求 / 课程容量 10 / 100 个不同学生**
3. 点「开始实验」，三种实现依次跑完，结果对比：

| 实现 | 实际落库 | 超卖 | 防重复选 |
|---|---|---|---|
| 朴素实现（先查后写） | **100 人** | **超卖 90** | 不能 |
| 朴素 + 唯一索引 | **100 人** | **超卖 90** | 能 |
| 条件扣减（原子） | **10 人** | **0** | 能 |

4. 把「请求来源」改成「同一个学生点 100 次」再跑一遍：

| 实现 | 实际落库 | 重复记录 | 拒绝原因（界面会显示） |
|---|---|---|---|
| 朴素实现 | **100 条** | **99 条重复** | — |
| 朴素 + 唯一索引 | 1 条 | 0 | 唯一索引冲突：已选过这门课 × 99 |
| 条件扣减（原子） | 1 条 | 0 | 你已选过这门课 × 99 |

**要讲的结论**：两道防线缺一不可 ——
唯一索引 `UNIQUE(student_id, offering_id)` 防重复选，条件更新 `WHERE selected_count < capacity` 防超卖。
只做其中一道，真实抢课场景下一定会出错。
另外注意两者的**拒绝原因不一样**：唯一索引抛的是数据库错误，原子版给的是业务提示 ——
前者会直接把 DB 异常暴露给用户。

### 8. AI 选课推荐（能解释、能被追问）
1. 左侧「AI 选课推荐」→ 顶部四张卡是学生画像：已修学分 / 本学期已选 / 主修方向 / 可推荐门数
2. 每张推荐卡有总分和一条**贡献条**，五段颜色对应五个维度，长度就是该项得分
3. 点「评分明细」→ 逐项列出得分和依据（"已修 1 门同方向课程"、"上课(ARC101)，正好差一个层级"）
4. 点「**选这门课**」→ 列表立刻重算：已选学分 +3、可推荐门数 -1、后面几门名次前移
5. 拉到底部「为什么只推荐这几门」→ 硬约束筛掉的每一类都给了门数，加起来等于全部教学班
6. 换个学生登录（`2023002`）→ 首位推荐变了（专业不同，方向权重不同）

**要讲的结论**：这是**规则引擎，不是大模型**。每一分都能对上一条具体数据，所以能解释；
接真模型只需要替换 `AI.provider`，页面和调用方都不用改。
演示里故意做成可追溯，就是为了避免"AI 说了算、问不出为什么"。

### 9. 学业预警（三端 + 生命周期）

1. 左侧「学业预警」→ 默认是**我的预警**：26 分、黄色「预警」
   - 注意这个人 **出勤 3/3 全勤**，问题全在作业 —— 只看出勤会把他漏掉
2. 点「证据」→ 展开 5 份逾期作业，每份都写着截止时间和"已关闭补交 / 仍可补交"
3. 切「班级名单」→ 《BIM 建模与协同》31 人里 17 人触发，按等级和风险分排序
   - 点任意一行的「证据」→ 展开该学生的全部命中规则
   - 点「干预」→ 写一句说明保存 → 状态变「已干预」
4. **关键一步**：干预后回「我的预警」→ 等级没变，预警还在
   —— 干预只是留痕，不会消掉预警
5. 去「我的作业」补齐那几份逾期 → 回「学业预警」
   → **时间线里多一条「自动解除」**，等级回到「正常」
6. 切「全校分布」→ 9 严重 / 10 预警 / 16 关注 / 55 正常，下面有规则命中排行

**要讲的结论**：预警的价值不在"标红"，在**可解释 + 可解除**。
每条预警都能追问到具体记录；解除只能靠重算（补齐作业），不能靠人点掉 ——
否则这套系统就成了"点一下就没事了"。

阈值也不是拍脑袋定的：学分规则用「落后中位数 ≥ 10 **且** 低于 26 学分」双条件，
因为这套种子数据的学分是分档的（20/26/32/38/44），单用绝对阈值会把整档学生一次性标红。
实测命中 18/90 = 20%，全校正式预警率 21.1%，分布有区分度。

## 数据自洽（被问到"数据怎么保证一致"时这么答）

演示数据最容易出的不是崩溃，而是**数字之间对不上** —— 老师随手一加就发现了。
下面这几条不变量都写成了断言，`node selftest.js` 每次都会验：

| 不变量 | 为什么需要 |
|---|---|
| 每门课的 `selectedCount` = 真实选课行数 | 否则统计有 31 人、名单里只有 1 人 |
| 每次签到的**星期**落在该教学班的排课星期上 | 否则「课表写周二有课，签到记录却在周五」 |
| 签到日期不晚于今天 | 防止种子数据写了未来日期 |
| 作业四档筛选之和 = 全部 | 否则「全部 6，但两档加起来 5」 |
| 各方向教学班之和 = 全部教学班 | 防止分类漏掉某个方向 |
| AI 推荐各筛选分支之和 = 全部教学班 | 否则"16 门里剔掉 9 门"，剩下 8 门就说不通 |

出勤率、名单、平均分这些数字都是**算出来的**；只有日期和种子值是人写的，
所以专门守这两类。

## 已知边界（别在答辩时被问倒）

- **不是真并发**。浏览器是单线程，实验用 `await` 让出事件循环来复现"判断与写入之间的间隙"。这个间隙在真实系统里就是网络往返 + 线程调度，所以竞态是真的，只是放大了。
- **文件上传是假的**。只记录文件名和大小，不做真实上传。真实系统要限制类型、重命名、防路径穿越。
- **没有权限校验**。前端能改任意数据。真实系统必须服务端校验 + 越权检查（学生 A 不能查学生 B）。
- **签到没有防代签**。真实系统还需要定位围栏 / 设备指纹 / 二维码签名。
- **教师端只有一个演示入口**，真实系统里教师只能操作自己开的课。
- **候补没有"确认递补"环节**。演示里是自动补位；真实系统通常会给学生一个确认窗口（比如 2 小时内确认，否则顺延给下一位）。
- **消息推送是本地写入**，没有真实的推送通道（短信 / 站内信 / WebSocket）。
- **统计都是实时全量计算**。数据量大了要预聚合或走物化视图，不能每次扫全表。

完整设计方案（含数据模型、接口草案、分期路线）见上一级目录的 `选课网站设计方案.md`。
